# Checklist สาธิตและตอบคำถามโครงงาน DengueYosoku

ใช้เวลาแนะนำประมาณ 8–10 นาที ปรับตามเวลาที่ได้รับจริง

## ก่อนวัน/ก่อนเข้าห้องนำเสนอ

- [ ] แตก ZIP และตรวจว่าเปิดโฟลเดอร์ `dengueguard-vercel` ถูกต้อง
- [ ] ติดตั้ง Node.js 20.9+ และ dependencies ด้วย `npm install`
- [ ] ทดลอง `npm run dev` และเปิด <http://localhost:3000>
- [ ] ทดลอง build: `npm run typecheck` และ `npm run build` (PowerShell บน Windows ใช้ `npm.cmd` ได้)
- [ ] ตรวจว่า Health Assistant แสดงสถานะ AI พักการพัฒนา และไม่แสดงช่องส่งคำถาม AI
- [ ] เตรียมเปิด `/alerts` และทดสอบสถานการณ์จำลองก่อนเริ่มนำเสนอ
- [ ] ตรวจว่าไม่มี `.env.local`, API keys, Supabase secrets หรือข้อมูลผู้ป่วยใน ZIP
- [ ] เตรียมภาพหน้าจอสำรองกรณีอินเทอร์เน็ตหรือบริการภายนอกขัดข้อง
- [ ] หากใช้ Vercel Preview ให้ตรวจ deployment commit SHA ให้ตรงกับซอร์สที่นำเสนอ

## ลำดับสาธิต

### 1. Dashboard — ภาพรวมระบบ (ประมาณ 1 นาที)

- เปิดหน้า Dashboard
- อธิบายว่าหน้านี้รวมข้อมูลเฝ้าระวังและแนวโน้มเพื่อช่วยให้ผู้ใช้เข้าถึงข้อมูลได้ง่าย
- ชี้วันที่อ้างอิง แหล่งที่มา และขอบเขตจังหวัดให้ผู้ชมเห็น
- เปิด Popup รายงานพยากรณ์เพื่อแสดงสัปดาห์เป้าหมาย ยอดรวม ค่าเฉลี่ย อันดับจังหวัด และสถานะ Snapshot
- ย้ำว่า report ระดับประเทศไม่ใช่ผลพยากรณ์รายจังหวัด และแผนที่ ODPC4 เดิมเป็นข้อมูลประวัติศาสตร์

### 2. Prevention — การป้องกัน (ประมาณ 45 วินาที)

- เปิดหน้า Prevention
- เริ่มจากแถบหัวข้อป้องกันโรคเชิงรุกที่อยู่บนสุดของหน้า
- แสดงคำแนะนำ 3 เก็บและ checklist รายสัปดาห์
- อธิบายว่าผู้ใช้สามารถนำรายการไปใช้ตรวจสอบพฤติกรรมในครัวเรือนได้

### 3. Symptom Checker — สัญญาณอันตราย (ประมาณ 1 นาที)

- เปิดหน้า Symptom Checker
- ใช้ตัวอย่างสมมติเท่านั้น ห้ามใช้ข้อมูลผู้ป่วยจริง
- แสดงการคัดกรองสัญญาณเตือนและข้อความแนะนำให้ขอความช่วยเหลือ
- ย้ำว่าแบบประเมินไม่ใช่การวินิจฉัยและไม่ควรชะลอการไปโรงพยาบาลเมื่อมีสัญญาณอันตราย

### 4. Knowledge / Health Assistant — องค์ความรู้และหลักฐาน (ประมาณ 1 นาที)

- เปิด Knowledge และแสดงที่มาของเนื้อหา
- เปิด Health Assistant เพื่อแสดงสถานะว่า AI พักการพัฒนาไว้ก่อน
- ขยาย “คลังความรู้และหลักฐาน (Evidence-only)” แล้วค้นคำทั่วไป เช่น “สัญญาณเตือนไข้เลือดออก”
- แสดงรายการเอกสารและแหล่งอ้างอิง โดยย้ำว่าเป็นการค้นคืนหลักฐาน ไม่ใช่คำตอบที่สร้างด้วย AI
- ไม่ต้องเปิดหรือทดสอบ AI Gateway ในการนำเสนอครั้งนี้

### 5. Model Operations — ความพร้อมของโมเดล (ประมาณ 1 นาที)

- แสดงหน้าสถานะ diagnostics/readiness
- อธิบายว่าระบบตรวจความครบถ้วน, freshness และ integrity ก่อนอนุญาตให้ downstream ใช้ผล
- หากสถานะเป็น missing/blocked ให้ถือว่าเป็นผลที่ถูกต้องตาม fail-closed policy ไม่ใช่สร้างตัวเลข forecast ขึ้นมาแทน
- แยกให้ชัดระหว่าง legacy 8-province history กับสายงานพัฒนาโมเดล 77 จังหวัด

### 6. Alert Center — สนามจำลองระบบแจ้งเตือนระดับประเทศ (ประมาณ 2 นาที)

- เปิด `/alerts` และชี้ป้าย DEMO ONLY / ข้อความข้อมูลสังเคราะห์
- เลือกสถานการณ์ “เหตุการณ์ผสม” แล้วกด “จำลองการประเมิน”
- แสดง KPI จำนวน ALERT, WATCH และเหตุการณ์ค้างดำเนินการ
- เปิดตารางผลจำลองรายจังหวัดเพื่อให้เห็นรายการ 77 จังหวัดและค่าตัวอย่าง
- ทดลองค้นหาจังหวัด แล้วรับทราบ/ปิด/เปิดเหตุการณ์ใหม่
- ทดลองส่งตัวอย่างเข้าขั้นตอนทบทวน แล้วแสดงผล “ผ่าน (ตัวอย่าง)” หรือ “ขอแก้ไข” ให้เห็นว่าเป็น Workflow จำลอง
- ส่งออก CSV ตัวอย่าง และชี้ว่าชื่อไฟล์/ข้อมูลระบุ DEMO ONLY
- ย้ำว่าการจำลองไม่บันทึกการอนุมัติจริง ไม่สร้างสถานะเตือนภัยจริง และไม่ส่ง LINE/Email/SMS

### 7. สรุปผลและข้อจำกัด (ประมาณ 45 วินาที)

- แสดง CI workflow ที่ผ่าน
- อธิบายว่า CI ผ่านเป็นหลักฐานการทดสอบโค้ด ไม่ใช่การรับรองทางการแพทย์
- ปิดด้วยแผนงานข้อมูลสด 77 จังหวัด, independent evaluation, clinical review และ Preview smoke test

## ตัวอย่างคำถามที่อาจถูกถาม

**ถาม: ระบบพยากรณ์ได้ครบ 77 จังหวัดแล้วหรือยัง?**  
ตอบ: มีสายงานพัฒนาและประเมินโมเดล 77 จังหวัดแล้ว แต่ยังไม่เปิดผลเป็นการพยากรณ์ปัจจุบันที่ใช้ตัดสินใจจริง เพราะต้องมีข้อมูลสัปดาห์ล่าสุดที่ตรวจสอบได้และ release artifacts ผ่านเกณฑ์ก่อน

**ถาม: ทำไมแผนที่เดิมมีเพียง 8 จังหวัด?**  
ตอบ: แผนที่/แนวโน้ม ODPC4 เป็นชุดข้อมูลประวัติศาสตร์แยกจากสายงานโมเดล 77 จังหวัด การมีขอบเขตแผนที่ 77 จังหวัดไม่ได้หมายความว่ามีความเสี่ยงปัจจุบันครบทุกจังหวัด

**ถาม: ค่า metric ของโมเดลดีพอใช้งานจริงหรือไม่?**  
ตอบ: ผลที่มีเป็น retrospective benchmark ไม่ใช่ sealed blind test หรือ prospective clinical validation จึงใช้แสดงความคืบหน้าการพัฒนาเท่านั้น ยังต้องประเมินกับข้อมูลอนาคตที่ไม่เคยเห็นและเปรียบเทียบ baseline อย่างเป็นอิสระ

**ถาม: AI ตอบคำถามสุขภาพได้หรือไม่?**  
ตอบ: ในเวอร์ชันสาธิตนี้พักการสร้างคำตอบด้วย AI ไว้ก่อน แต่ยังค้นคืนหลักฐานและแสดงแหล่งอ้างอิงจากคลังความรู้ได้ ระบบไม่วินิจฉัยและไม่ใช้แทนแพทย์

**ถาม: ระบบแจ้งเตือนระดับประเทศทำอะไรได้แล้ว?**  
ตอบ: มีสนามจำลองเพื่อทดลองสถานการณ์ ผลรายจังหวัด การจัดการเหตุการณ์ และ Workflow ทบทวนได้ แต่ผลทั้งหมดเป็นข้อมูลสังเคราะห์เพื่อสาธิต ไม่ใช่การแจ้งเตือนจริง โดย Rule Profile และ threshold ยังไม่ผ่านการอนุมัติ

**ถาม: CI ผ่านหมายถึงระบบใช้งานจริงได้แล้วหรือไม่?**  
ตอบ: CI ยืนยันว่าโค้ดใน commit นั้นผ่านชุดตรวจที่ตั้งไว้ แต่ไม่ได้ยืนยันข้อมูลปัจจุบัน การ deploy สำเร็จ การตรวจสอบความปลอดภัยทุกด้าน หรือการรับรองทางการแพทย์

## สิ่งที่ไม่ควรกล่าวอ้าง

- ห้ามกล่าวว่าโมเดล 77 จังหวัดเป็น live forecast หากข้อมูลและ release gate ยังไม่ผ่าน
- ห้ามกล่าวว่าแผนที่ ODPC4 เป็นความเสี่ยงปัจจุบันครบ 77 จังหวัด
- ห้ามกล่าวว่า AI สร้างคำตอบได้ในเวอร์ชันสาธิตนี้ หรือได้รับการรับรองทางคลินิก
- ห้ามกล่าวว่าผลจำลองใน Alert Center เป็นสถานการณ์เฝ้าระวังจริง หรือส่ง LINE/SMS/Email อัตโนมัติแล้ว
- ห้ามกล่าวว่า Preview ล่าสุดออนไลน์แล้วโดยไม่ตรวจ SHA และสถานะ Deployment
- ห้ามใช้ข้อมูลผู้ป่วยจริงในการสาธิต
